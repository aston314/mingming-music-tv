# Android 6 界面与焦点验证（2026-11-18）

## 改动

- 左侧导航的六个页面均不再生成右侧歌词/评论区域，内容占满可用宽度；从底栏封面进入全屏后显示歌词/评论。
- 检测 Grid 和 flex gap 的实际支持情况；不支持时使用 flex 布局、明确的行列间距和正方形封面。旧 WebView 保留主题颜色、全屏弹窗和圆角焦点环。
- 修正 Logo 与名称间距、底栏和列表操作间距，以及“我的”圆形图标被 flex 压扁的问题。
- 侧栏上下键先走侧栏路径；歌曲行按目标行移动。焦点记忆只保存 DOM 位置，在目标被移除后才寻找附近的可用目标，避免逐项测量隐藏操作按钮。
- 原生播放轮询只在状态变化时更新歌曲/按钮；进度、图标和循环方式按实际变化写入。普通导航页不再持续更新隐藏歌词。
- 网易云封面按展示请求 160（行/底栏）、300（卡片）、400（全屏）尺寸，不修改原歌曲数据。
- 原生 Back/Escape 在释放时交给页面返回处理。页面不可用时使用系统退出确认，默认取消；确认退出后停止服务。系统弹窗存在时不把方向键转发给网页。

## 本地回归

通过 ES5 解析、项目契约、Python 脚本测试、Go race/vet 和完整浏览器回归。

浏览器包含六个导航页、四方向焦点、弹窗返回、全屏歌词/评论、评论分页、播放列表、扫码登录、暂停恢复、seek、切歌和异步响应隔离。布局覆盖 960×540、1280×720、1920×1080、4:3、16:10 和宽窗口；另有缺少 Grid/gap/CSS 变量的能力模拟。

`tests/focus-performance-browser.cjs` 比较 24/240 首歌，验证单步焦点的几何读取不随歌曲数量增长、侧栏不测量内容/隐藏播放器，以及暂停原生轮询 1.1 秒没有无效 DOM 改写。

## 实机方式与界限

- ZIDOO X9S，Android 6.0.1 / API 23，WebView Chromium 44.0.2403.119。
- 已安装应用 0.1.11 / code 12；物理输出 1920×1080，WebView CSS 视口 1280×720，逻辑画布 1280×720。
- 通过已安装应用的 DevTools，在独立临时 iframe 内运行修改后的完整 UI。未构建或安装 APK；此方法可验证旧引擎渲染和页面按键路由，不能验证新 Java 壳的 Back 分发。
- 实际检测 Grid、flex gap 均不支持。真实页面检查：Logo 间距 18px，“我的”图标 112×112px，歌单/专辑四列，封面 204×204px；导航页右缘到达逻辑画布 1280px。
- 真实页面和独立测试场景分开。百首歌对照使用相同只读展示数据与暂停的原生播放模拟，网络和写入在临时页面中截断；不修改真实收藏、账号和队列。宿主仍有原应用，因此绝对帧率不能据此推断。

## 百首歌同设备对照

100 首歌曲加顶部当前歌曲行，焦点从固定行开始，下五次、上五次，重复两轮；每步间隔 250ms。表中为 20 次单步记录。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 处理耗时中位数 | 35.39ms | 12.69ms |
| 处理耗时 P95 | 48.40ms | 17.24ms |
| 到下一次 requestAnimationFrame 中位数 | 37.27ms | 17.99ms |
| 到下一次 requestAnimationFrame P95 | 54.59ms | 27.80ms |
| 内容区几何/样式读取次数（每步） | 811 | 6 |

这些是按键路由和下一帧回调的时间，不等于屏幕显示延迟或应用帧率。`gfxinfo` 的窗口累计指标仍显示较高的慢绘制比例，不能声称所有卡顿已经消失。

短时 DevTools tracing 成功完成，保留去内容后的 DrawFrame/RasterTask 计数；旧引擎未返回可用的布局/绘制时长。`atrace` 在限定时间内未正常结束，不把其输出作为性能结论。原始 trace、账号、地址和页面截图不提交到仓库。

实体遥控优化前已采样：左侧下五次、上五次路径正确，未测量内容区；优化后同操作待补充。新 Java 退出路径仍需 Android 编译/lint 与更新后的签名 APK 实机验证。
